# D1 当日读取额度耗尽

## 已核查证据

- Worker 仍绑定原数据库 `server-monitor-db`，数据库 ID 为 `f7df202e-ddb6-44cf-92fa-890cb111004e`。
- D1 仪表盘显示约 50.34 MB、17 张表。控制台执行只读节点计数时，明确返回账户超过免费每日行读取限制。
- 页面之所以显示空列表、默认标题与主题，是设置和节点读取错误被吞掉后使用了默认值；不能将该表现当作记录删除。
- 过去 24 小时的指标显示：调度审计清理 `DELETE FROM iperf_dispatch_audit WHERE observed_at<?` 执行 870 次，读取约 279 万行；该表缺少时间索引。历史采样查询另读取约 140 万行。24 小时统计窗口不等同于 UTC 额度日，不能直接用两者总和断言当天精确占比。

## 修复

- 调度审计增加 `observed_at` 索引，范围清理采用索引；以 SQLite 查询计划回归验证。
- 清理由每分钟降为每小时，沿用 7 天保留期限，不删除业务数据。
- 数据库额度错误向外传播，不再返回默认权限、默认外观或空节点；入口返回明确的 HTTP 503 与中文故障说明，并禁止缓存故障页面。
- 不升级付费计划、不重建数据库、不回滚历史数据。免费额度按 UTC 00:00，即北京时间 08:00 重置，随后复核节点、主题及上报恢复。
