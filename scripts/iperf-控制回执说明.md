## 修复范围

HKG、HKS 使用 `listener_mode: receipt`。HKS 通过已有 Tailnet SSH 控制临时监听，减少监听命令与回执往返 CF 的依赖。测速仍从 deb 到节点公网，原定时、时长、探针和 SSH/Tailscale 配置保留。

`iperf-control.py` 和 `iperf-runner.py` 必须一起部署到 deb `/root/`。两台节点静态助手位于 `/opt/cfsm-iperf-control/node.py`；没有新增常驻监听。

## 防止重现

1. 先只读预检，分开记录 Tailnet 建连与创建监听阶段。
2. 用 job_id 唯一的 systemd unit 和 `/run/cfsm-iperf-control/<job_id>.json` 保存状态。
3. 启动回复丢失时只查询同一任务，不盲目重复启动或重复测速。
4. 启动调用前就登记清理对象，异常仍执行同任务停止与回执核对。
5. systemd 最长 600 秒，助手自行回收子进程和仅属本任务的临时规则；正常结束再核对原 5201、临时 5202 和规则。
6. 日志分别记录 operation、耗时、回执、SSH 异常；HTTP 错误记录状态码与精简正文，不记录认证头和令牌。
7. `npm run test:control` 覆盖回复丢失不重启、失败回执不冒充就绪、清理重入；`test:all` 已纳入该门禁。
